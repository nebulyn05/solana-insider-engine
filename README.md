# Solana Insider Tracking & Proactive Execution System\n\nMainnet-first Solana observation and paper-trading backend.\n\n## Runtime boundary\n\n- **Network:** Solana mainnet-beta.\n- **Data:** live mainnet observations.\n- **Execution:** paper trading only.\n- **Signing/broadcast:** disabled. No private key or transaction submission path is enabled.\n- **Simulation:** simulated entries/exits are written to PostgreSQL using observed mainnet prices and configurable execution/slippage models.\n\n## Unified live engine\n\nApply database migrations, configure .env, add tracked wallets, then run:\n\n`python scripts/run_live_engine.py`\n\nThe supervisor runs:\n\n1. Mainnet WebSocket wallet observation.\n2. Transaction recovery after reconnects using a durable checkpoint.\n3. Mainnet transaction decoding with DEX evidence.\n4. Deduplicated DEX trade observations.\n5. Sliding warm-wallet clustering.\n6. Signal scoring and persisted component breakdown.\n7. Paper-only entry simulation with dynamic liquidity/volatility/latency slippage.\n8. Continuous paper TP/SL/time-expiry monitoring.\n9. Social co-occurrence confirmation polling.\n10. Structured PostgreSQL execution/observation records.\n\nThe engine does **not** sign, broadcast, or submit a Solana transaction.\n\n## DEX detection\n\nA token balance increase alone is not treated as a buy anymore. A candidate must have explicit configured DEX/router program participation or swap-log evidence.\n\n`DEX_PROGRAMS` accepts:\n\n`PROGRAM_ID=NAME,PROGRAM_ID=NAME`\n\nOrca Whirlpools is included by default. Add the exact mainnet program IDs for the routers/DEXs you want to observe. This keeps the decoder explicit rather than silently classifying arbitrary transfers as buys.\n\n## Recovery and deduplication\n\nThe live stream stores:\n\n- `stream_checkpoints` for last processed slot/signature.\n- `observed_transactions` for transaction-level deduplication.\n- `dex_trade_observations` for normalized DEX evidence.\n\nOn reconnect, the engine asks mainnet for recent signatures for each tracked wallet and replays transactions newer than the stored checkpoint. Duplicate transactions are ignored.\n\n## Paper execution model\n\nPaper entries use:\n\n- observed mainnet SOL/token price;\n- configurable paper notional;\n- configurable synthetic liquidity;\n- volatility and network-delay penalties;\n- simulated slippage;\n- PostgreSQL lifecycle events.\n\nThe position monitor uses the latest observed token-buy mark and closes paper positions on take-profit, stop-loss, or maximum hold time.\n\n## Required configuration\n\nCopy `.env.example` and provide `DATABASE_URL`.\n\nRequired safety settings:\n\n- `SOLANA_NETWORK=mainnet-beta`\n- `PAPER_TRADING=true`\n- `LIVE_EXECUTION=false`\n\nHistorical Devnet rows may remain in the database; new engine records default to mainnet-beta.
